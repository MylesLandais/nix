# Warcraft III Reforged on NixOS (Cerberus), October 2026

This is a compatibility review and read-only diagnostics handoff. It is **not** evidence of a successful on-host launch; no Nix evaluation or NVIDIA/Hyprland session was available from this workspace.

## Steam Deck / Arch lessons

- Some SteamOS players run Warcraft III Reforged through Proton, but historical Steam Deck reports also contain black menus and freezes. SteamOS uses AMD graphics, so copy the **runner strategy**, not its GPU tuning.
- Reforged 3.0 introduced a CERT_CHAIN_ENGINE_CONFIG certificate incompatibility. GE-Proton 11-7 and Wine 11.6+ have the relevant fix; old Wine/Proton builds can show misleading VPN errors.
- BlizzardBrowser renders the in-game menu using D3D11 shared textures. DXVK 3.0.2 resolves the documented black-menu regression (#5916).
- DXVK 3.x stores a shader cache inside Wine AppData/Local by default. Preserve the cache between warm-launch tests.
- Nested Gamescope may isolate presentation; on NVIDIA it can also introduce its own problems. Test direct XWayland first.
- A September 27 community Proton fork addressed VirtualQueryEx-induced W3Champions stutter. That is specific to W3Champions, not a general Warcraft fix.
- Proton outside Steam should run through umu-run. Keep separate prefixes for Wine and GE-Proton experiments.

## Findings from the connected Cerberus flake

1. The repository already enables Gamescope, GameMode, NVIDIA graphics including 32-bit support, and DRM modesetting. Do not add redundant flags.
2. The Home Manager Hyprland startup code forcibly stopped then restarted hyprland-session.target. This draft removes the destructive stop.
3. The display-manager session is pinned to plain hyprland, not UWSM. Do not switch to UWSM without coordinating Home Manager systemd integration.
4. XDG portals are configured across NixOS and Home Manager. Verify active backends and user-manager environment before consolidating them.
5. Noctalia has both a compositor startup path and a Home Manager activation restart path. This merits a lifecycle cleanup after auditing.
6. Workspace recovery reacts to monitor events; HEADLESS-1 is created on startup. Compare a game session with and without the headless output.
7. The committed flake.lock pins nixpkgs to 59e69648d345d6e8fef86158c555730fa12af9de from August 2025, **before DXVK 3.0.2 existed**. Reconcile the local lock file and installed Nix generation before enabling the previously shared v2 Warcraft module. Do not mass-update the whole flake in this PR.
8. Cerberus is configured for GPU-backed LLM services. Game load times can be degraded by VRAM pressure on the single NVIDIA card; collect GPU memory usage during the slow load.
9. Non-Kali desktop entries are generally generated by Nix/Home Manager, not tracked as checked-in *.desktop files. Inspect actual XDG application/autostart/session directories **on the host**, not only this repository.

## Read-only diagnostics (enabled for Cerberus)

~~~sh
desktop-session-audit | tee /tmp/desktop-session-audit.txt
warcraft3-linux-audit | tee /tmp/warcraft3-linux-audit.txt
warcraft3-reforged doctor    # if the previously generated game module is installed

# Compare the actual flake-evaluated package versions
nix eval --raw .#nixosConfigurations.cerberus.pkgs.dxvk.version
nix eval --raw .#nixosConfigurations.cerberus.pkgs.wineWow64Packages.stagingFull.version

# Observe VRAM competition while loading a campaign
nvidia-smi --query-gpu=memory.used,memory.total,utilization.gpu --format=csv -l 1
~~~

The diagnostics enumerate XDG applications, autostart entries, and session entries, report shadowed IDs by search-path precedence, validate desktop files, and flag stale absolute TryExec paths. A shadowed entry is not necessarily broken. They do not edit entries, restart services, or mutate the Wine prefix.
